Question Link : https://www.geeksforgeeks.org/problems/attend-all-meetings-ii/1

* Problem:
  Given start and end times of meetings, find the minimum number of rooms required so that no overlapping meetings share a room.

* Key observation:
  The number of rooms required at any moment equals the number of meetings currently in progress.

* Sweep line idea:
  Represent every meeting using two events: START at its start time and END at its end time.

* Event representation:
  Meeting [start, end] -> (start, START) and (end, END).

* Why sweep line works:
  Process events chronologically and maintain the number of currently active meetings.

* Event data structure:
  TreeMap<int[], Integer> stores events in sorted order and maintains a frequency for identical events.

* Why TreeMap?
  Events must be processed from earliest time to latest time, so TreeMap provides the required ordering.

* Why store frequency?
  Multiple meetings can have the same event time and type, so one TreeMap entry can represent all identical events.

* Event ordering:
  Events are sorted first by time and then by event type.

* Important consequence:
  END = -1 is processed before START = 1 when both occur at the same time.

* Why process END before START?
  A meeting ending at time t does not overlap with a meeting starting at time t, so the same room can be reused.

* activeRooms:
  Represents the number of meetings currently occupying rooms.

* START event:
  Increase activeRooms by the number of meetings starting at that time.

* END event:
  Decrease activeRooms by the number of meetings ending at that time.

* maxRooms:
  Stores the maximum number of simultaneously active meetings encountered during the sweep.

* Example:
  Meetings [1,5] and [5,10] require only 1 room because the first meeting ends exactly when the second begins.

* Therefore:
  Processing END before START at the same timestamp correctly allows the room to be reused.

* Time Complexity:
        
        O(n log n).

* Space Complexity:
        
        O(n)
